# PokemonCard 攻击校验接口

更新日期：2026-09-22

文档修订：第 3 版。所有响应仅通过 HTTP 状态码表达结果，响应体为空；请求字段及三种攻击数值保持不变。

**接入状态：待后端实现。** 本文是新的前后端接入约定。目前 MR !5 仍使用旧接口结构，暂时不能直接用本文的两字段请求联调；我会在后端调整完成后同步。

## 1. 调用方式

前端调用 battle，battle 将请求中的两个字段转发给 attack；attack 比较该攻击类型的固定伤害与上报数值，只返回 HTTP 状态码，响应体为空。battle 不自行比较伤害，收到 attack 的最终 HTTP 响应后，原样转发状态码，并保持响应体为空。

例如 attack 返回 200、400、422 或 500，battle 就分别返回同一个状态码。只有未取得可用 HTTP 响应时，battle 才按通信故障返回 502、503 或 504；battle 自身出现可处理的内部异常时返回 500。

前端不再请求规则接口，后端不再对外提供规则查询或使用规则文件。双方按下表约定三种攻击及其固定数值。

| attack_type     | expected_damage |
| --------------- | ---------------:|
| enemy_collision | 7               |
| collision       | 18              |
| throw           | 20              |

以上映射按字符串精确对应，特别是 `enemy_collision` 对应 7，`collision` 对应 18。

## 2. 请求

| 项目           | 内容                         |
| ------------ | -------------------------- |
| 方法           | POST                       |
| 路径           | /api/v1/attack-validations |
| 本地 battle 地址 | http://127.0.0.1:8080      |
| Content-Type | application/json           |

请求体仅包含以下两个字段：

| 字段              | 类型      | 必填  | 说明                                     |
| --------------- | ------- | --- | -------------------------------------- |
| attack_type     | string  | 是   | 三种攻击之一：enemy_collision、collision、throw |
| expected_damage | integer | 是   | 前端本次上报的名义伤害数值，例如 20；使用数字，不使用字符串        |

这里的 `expected_damage` 是前端提交、等待后端校验的数值。attack 按自身约定的固定数值比较，不直接认定前端提交的值正确。

三种正常请求：

```json
{"attack_type":"enemy_collision","expected_damage":7}
```

```json
{"attack_type":"collision","expected_damage":18}
```

```json
{"attack_type":"throw","expected_damage":20}
```

不再提交角色编号、对局编号、事件编号、规则版本或其他业务字段。本版仅进行伤害数值比较，不增加身份、攻击频率、对局状态等业务校验。

## 3. 校验结果

前端仅按 HTTP 状态码区分结果：

- `throw` 上报 20：返回 **HTTP 200**，响应体为空。
- `throw` 上报 999：返回 **HTTP 422**，响应体为空，前端提示对局失败，退出对战界面。

所有成功和失败响应均无 JSON、文本或其他响应体，不返回 valid、message、伤害值或编号，也不返回空 JSON 对象。前端读取 `response.status`，不要调用 `response.json()`；页面提示文字由前端按状态码自行提供。

“校验通过”不代表后端已确认游戏命中或完成扣血。后端不保存或修改血量，血量、动画和胜负由前端管理。

## 4. 状态码与异常响应

下表是简化接口拟保留的状态码；旧版本的完整错误码列表不作为本文的接入约定。

| HTTP 状态码 | 触发情况                                             | 前端处理                     |
| -------- | ------------------------------------------------ | ------------------------ |
| 200      | attack 判断攻击类型对应的固定伤害与上报数值匹配                      | 确认属于当前有效攻击后，按本次提交的伤害扣血一次 |
| 400      | attack 无法将请求解析为约定的两个字段，例如 JSON 损坏或伤害不是整数         | 检查请求格式，不扣血               |
| 422      | 请求可正常读取，但上报伤害与该攻击类型的固定数值不匹配                      | 提示伤害不匹配，前端退出对局战斗         |
| 500      | attack 返回内部错误，battle 原样转发；或 battle 自身发生内部异常且仍能响应 | 提示服务异常，不扣血               |
| 502      | battle 与 attack 通信时取得的响应不符合 HTTP 协议，例如响应状态行损坏    | 提示服务异常，不扣血               |
| 503      | battle 无法连接 attack，例如 attack 未启动或连接被拒绝           | 提示服务暂不可用，不扣血             |
| 504      | battle 等待 attack 超时，沿用当前默认 500ms 的业务调用预算         | 提示请求超时，不扣血               |

400 只用于无法读取本次校验输入的基本格式问题；本版不扩展其他参数校验规则。超时是 504，不是 500；500ms 是内部调用的默认时间预算，不保证浏览器在恰好 500ms 时收到响应。

上表所有状态的响应体都为空。空响应体是正常约定，不能据此返回 502；battle 不再检查响应 JSON 或业务响应字段。attack 返回的 5xx 也原样转发，不统一改成 503。

422 是业务校验未通过，5xx 是服务处理或通信故障，前端分别提示。若 battle 本身未启动或连接中断，浏览器可能只有网络错误，没有 HTTP 状态码，同样不扣血。

## 5. 最小联调验收

- 三个正常请求分别返回 200，前端分别扣血 7、18、20。
- throw 上报 999，attack 返回 422；battle 原样转发该状态码，前端直接退出对局战斗。
- 所有成功和失败响应的响应体均为空，前端不尝试解析 JSON。
- 无法解析的 JSON 或非整数伤害返回 400，与数值不匹配的 422 分开处理。
- 目标只剩 3 HP 时，throw 仍上报 20；校验通过后前端将血量截断为 0。
- 停止 attack 后发起请求，battle 返回 503，前端提示服务不可用。
- 模拟 attack 返回 500，battle 仍返回 500，不转换成 503。
- attack 超过调用预算仍未完成响应，battle 返回 504，前端提示超时。
- 请求期间重开游戏，旧请求结果不影响新一局；前端自行避免一次命中被重复扣血。


## 6. 开发模式

**本次新增需求（2026-09-28，待实现）：** 以下第 6—9 节为新增开发接口约定，需在对应后端代码实现后使用，不表示这些接口当前已经可用。

开发模式用于前后端联调和错误场景测试，不改变正常攻击校验规则。battle 和 attack 启动时加载 `backend/.env` 中的配置，并读取 `APP_ENV` 决定是否开放开发接口；启动日志明确记录开关状态。已有进程环境变量优先于 `.env`，包括已设置为空值的情况。

| APP_ENV 配置 | 开发接口 |
| --- | --- |
| dev | 开启 |
| prod | 关闭 |
| 未设置、空值或其他值 | 关闭 |

值按 `dev` 精确匹配。环境变量在启动时读取，修改后需重启对应服务。前端不能通过请求字段或请求头开启后端开发模式。该开关用于区分运行环境，不提供开发者身份认证；开发模式开启时，可访问服务的调用方即可使用开发接口。

以下为代码实现后的配置与启动方式。

### 6.1 首次配置（只需一次）

仓库提供 `backend/.env.example`，默认内容为：

```dotenv
APP_ENV=prod
```

首次克隆项目后，在 `backend` 目录执行：

```powershell
Copy-Item .env.example .env
```

需要开发模式时，将生成的 `.env` 中配置改为：

```dotenv
APP_ENV=dev
```

`.env` 会保存在本机，关机或重开终端后无需再次复制；已有文件不要覆盖。仓库提交 `.env.example`，实际 `backend/.env` 加入 Git 忽略列表，不提交。

### 6.2 日常启动

两个终端都进入 `backend` 目录，两个服务读取该目录下同一份 `.env`。

attack 终端：

```powershell
go run ./attack
```

battle 终端：

```powershell
go run ./battle
```

不需要每次手动设置环境变量。若终端已设置 `APP_ENV`，以终端值为准；希望使用文件配置时，可先执行 `Remove-Item Env:APP_ENV -ErrorAction SilentlyContinue` 清除当前终端的旧设置。

关闭开发模式时，将 `.env` 改为 `APP_ENV=prod`，并重启两个服务；若进程环境中另有配置，需一并调整。仅修改文件不会改变运行中的服务。

`.env` 不存在时继续使用进程环境变量；两处都未设置 `APP_ENV` 时默认关闭开发接口。文件存在但无法读取或格式错误时，启动失败并提示配置错误。

## 7. 开发接口

前端开发面板统一调用 battle，由后端准备测试数据，不修改正常攻击接口的请求字段。

| 项目 | 约定 |
| --- | --- |
| 方法 | POST |
| 路径 | /api/v1/dev/{status} |
| 本地 battle 地址 | http://127.0.0.1:8080 |
| status | 200、400、422、500、502、503、504，按路径精确匹配 |
| 请求体 | 不需要，调用方应不发送请求体 |
| Content-Type | 无请求体，无须提供 |
| 响应 | 仅 HTTP 状态码，响应体为空 |

### 7.1 测试场景

| 路径 | 处理方式 | 正常测试条件下的预期状态码 |
| --- | --- | ---: |
| /api/v1/dev/200 | battle 向 attack 正常接口提交 throw、20 | 200 |
| /api/v1/dev/400 | battle 向 attack 正常接口提交未知类型 invalid、20 | 400 |
| /api/v1/dev/422 | battle 向 attack 正常接口提交 throw、999 | 422 |
| /api/v1/dev/500 | battle 调用 attack 开发接口，由 attack 返回 500 | 500 |
| /api/v1/dev/502 | battle 直接模拟网关错误状态，不调用 attack | 502 |
| /api/v1/dev/503 | battle 直接模拟服务不可用状态，不调用 attack | 503 |
| /api/v1/dev/504 | attack 开发接口延迟响应，触发 battle 的 500ms 调用超时 | 504 |

502、503 只模拟对应状态码，不代表实际发生了网络故障；504 通过真实调用超时产生。每次开发请求不自动重试。

attack 提供以下内部开发接口，仅在 attack 的 `APP_ENV=dev` 时注册，供 battle 调用，前端不直接访问：

- `POST /internal/v1/dev/500`：返回 500，响应体为空。
- `POST /internal/v1/dev/timeout`：延迟 600ms 后返回空的 200；battle 的调用预算为 500ms，因此预期先超时并向前端返回 504。请求取消时，attack 提前结束等待。

完整测试要求两个后端服务均开启开发模式。若仅 battle 开启开发模式，200、400、422 仍可调用正常 attack 接口；500、504 对应的内部开发路径未注册时，attack 返回的 404 由 battle 原样返回，不能强行覆盖成路径中指定的状态码。

### 7.2 调用示例与前端处理

点击测试按钮时，前端发送 `POST /api/v1/dev/{status}`，不带请求体。例如测试 500：

```powershell
curl.exe -i -X POST 'http://127.0.0.1:8080/api/v1/dev/500'
```

后端仅返回 HTTP 状态码，响应体为空。前端读取 `response.status`，结果在 Network 面板查看，不影响游戏状态。生产模式隐藏 dev 按钮。

## 8. 开发接口响应约定

| 请求情况 | 后端响应 |
| --- | --- |
| 开发模式已开启，测试条件正常 | 第 7.1 节对应的状态码 |
| 开发模式关闭 | 404 |
| 路径不支持 | 404 |
| 开发模式已开启，支持的路径使用 GET 等错误业务请求方法 | 405，响应头包含 Allow: POST |

以上响应体均为空。正常攻击接口保持原有约定。

## 9. 开发模式联调验收

以下条目为新增开发模式实现后的验收要求，尚非已完成测试的声明。

- 进程环境及 `.env` 均未设置 `APP_ENV` 时，battle 和 attack 的开发接口均返回空的 404。
- 只在 `.env` 设置 `APP_ENV=dev` 时，两个服务直接启动即可开放开发接口，重开终端后无需再次复制配置。
- 进程环境设置 `APP_ENV=prod`、`.env` 设置 `APP_ENV=dev` 时，开发接口仍关闭；进程环境已设置为空值时也不被文件值覆盖。
- 修改配置后重启两个服务，开发模式随之变化；配置文件格式错误时启动失败并提示错误。
- `APP_ENV=prod`、空值或其他非 `dev` 值时，开发接口仍关闭；请求不能通过自行添加字段或请求头开启它们。
- 两个服务均设置 `APP_ENV=dev` 时，第 7.1 节七个测试入口符合约定，响应体均为空。
- battle 关闭开发模式时，访问开发路径不会触发 attack 的故障逻辑。
- 只开启 battle 的开发模式时，调用未开启的 attack 内部开发接口返回 404，battle 保留该状态码。
- 未支持的开发路径返回 404，错误业务请求方法返回 405；如浏览器需要跨域预检，应能完成预检且不触发故障。
- 测试结果仅供 Network 面板检查，不影响游戏状态；浏览器网络失败没有 HTTP 状态码时也不影响游戏。
- 开关开发模式后，原有正常攻击校验的状态码与空响应体约定保持正确。
